# 웹툰 프론트엔드

Paperlogy와 흰색 배경을 유지하며, 즐겨보는 웹툰 1~3개로 종합 추천을 받는 React 앱입니다. 헤더와 브라우저 탭 이름은 “웹툰추천”입니다.

## 사용 흐름

1. 흰색 배경·회색 점선 테두리의 표지 크기 ＋ 카드를 눌러 검색창을 엽니다.
2. 제목 일부를 입력하면 200ms 디바운스 후 백엔드 검색 결과가 나타납니다.
3. 작품을 고르면 표지가 추가됩니다. 최대 3개, 중복 불가, 개별 삭제 가능.
4. 확인을 누르면 백엔드가 장르·태그·줄거리 유사도를 분석합니다.
5. 추가 질문 없이 바로 선택한 작품 정보와 최대 10개의 추천 작품을 순위와 추천 이유로 보여줍니다. 첫 결과는 최초 분석 응답을 그대로 사용합니다.
6. 결과 페이지는 왼쪽 선택 작품·오른쪽 추천 목록을 3:7로 배치합니다. 왼쪽은 상단 여백 24px의 sticky 열로 스크롤을 따라오며 “선택한 웹툰 바꾸기” 버튼도 같은 고정 영역에 포함합니다. 내부 스크롤·높이 제한을 제거하고 필터와 최대 3개 작품을 작은 표지, 제목, 작가, 플랫폼·상태, 한 줄 줄거리로 간결하게 배치합니다. 선택 작품 카드의 축소는 기존처럼 760px 이하 높이의 데스크톱에만 적용하며, 줄거리 한 줄 요약을 유지합니다. 필터 버튼 크기 조정은 카드 배치와 별도 조건으로 관리합니다. 960px 이하 너비에서는 고정을 해제하고 자연스럽게 세로 배치합니다.
7. 왼쪽 “당신이 좋아하는 이야기” 제목 위에서 플랫폼(전체/네이버/카카오)과 상태(전체/연재 중/완결(휴재))를 함께 필터링할 수 있습니다. 필터 그룹의 공통 배경·외곽선은 없으며 항목 사이에는 회색 ㅣ만 표시합니다. 선택한 글자 뒤의 은은한 박스가 선택 위치로 450ms 동안 이동하고, 모션 감소 설정에서는 즉시 이동합니다. 필터 변경 시 전체 후보를 대상으로 백엔드에 다시 요청하며, 카카오는 카카오웹툰과 카카오페이지를 포함합니다. 휴재작은 완결(휴재)에 포함되고 연재 중에서는 제외됩니다.
8. 추천 카드마다 실제 유사도를 0~100%의 원형 링으로 표시합니다. 필터 자체는 유사도를 올리지 않습니다. 필터를 변경하거나 전체 조건으로 초기화하면 추천 이력을 새로 시작하므로 이전에 본 작품도 다시 추천될 수 있습니다.
9. 하단 “재검색”은 선택 작품·현재 필터를 유지하면서 같은 조건에서 표시된 추천을 전부 제외합니다. 플랫폼 또는 연재 상태를 변경하거나 필터 초기화를 누르면 누적 이력을 비우고 새 조건에서 다시 추천합니다. 오류 재시도에는 이력을 유지하며 중복된 서버 응답도 화면에서 제거합니다. 이전 필터의 늦은 응답은 새 이력에 반영하지 않습니다. 후보가 부족하면 가능한 수만 표시하고, 모두 소진되면 안내합니다. 이력은 현재 필터 조건의 메모리에 보관하며 새 분석에서도 초기화됩니다. 오른쪽의 발견 개수는 화면에 표시하지 않으며 결과 변경은 스크린리더로 안내합니다.

검색·추천 후보는 백엔드가 배포에 포함된 `Backend/data/webtoons.json`에서 읽습니다. 유사도 계산은 백엔드에서 수행하며 Supabase는 조회하지 않습니다. 추천 개수는 JSON 후보 수에 따라 줄어듭니다. 선택한 작품은 추천에서 제외합니다. 없는 메타데이터는 표시하지 않습니다. 유사도가 0인 후보는 정보 부족 안내를 표시합니다.

## 실행

Node.js 22.12 이상이 필요합니다.

```bash
npm install
npm run dev
```

로컬은 `/api`를 `http://127.0.0.1:3001`로 프록시합니다. 별도 터미널에서 Backend를 실행해주세요. Vercel 배포에서는 `vercel.json`의 `/api/:path*` 규칙이 Railway 백엔드로 요청을 전달하며, 공개 페이지는 정적으로 생성하며, 알 수 없는 주소를 첫 화면으로 보내는 포괄 SPA 규칙은 사용하지 않습니다. 같은 도메인으로 API를 호출하므로 `VITE_API_URL`을 설정하지 않아도 됩니다. 다른 백엔드로 직접 연결하려면 해당 환경 변수를 설정하고 다시 빌드하며, 백엔드의 CORS에도 프론트엔드 도메인을 허용해야 합니다. 백엔드 주소를 변경할 때는 프록시 목적지도 함께 수정해주세요.

Backend에서 `npm run dev`를 실행하면 내부 JSON을 사용하는 API가 시작됩니다. Supabase 키는 필요하지 않습니다. Frontend의 `src/data/webtoons.json`을 갱신했다면 Backend에서 `npm run sync:catalog`로 배포용 JSON을 복사한 뒤 백엔드를 재시작해주세요. 프론트는 계속 검색·추천 API를 호출합니다.

- 진행률을 알 수 없는 분석은 무한 로딩바, 실제 응답 이후 완료 상태 표시

## SEO와 정적 공개 페이지

`npm run build`는 TypeScript 검사 → Vite 클라이언트 빌드 → 빌드 전용 React 렌더러 → 정적 HTML 생성 → SEO 산출물 검증 순서로 실행합니다. 빌드 시 네트워크·DB·Backend 실행은 필요 없습니다. 홈페이지는 동일한 React 트리를 HTML로 생성하고 `hydrateRoot`로 연결합니다. 작품·장르·가이드 페이지는 JavaScript 없이 읽을 수 있습니다.

- 공개 문서 43개: 홈페이지, 작품 목록, 작품 30개, 장르 7개, 가이드 2개, 소개·추천 기준. 별도 `404.html`은 noindex입니다.
- `src/seo/content.ts`에서 소개할 작품 ID와 직접 작성한 비교 문구를 관리합니다. 원본 줄거리를 그대로 재게시하지 않습니다. `src/data/webtoons.json`에서 없는 작품·중복 ID·잘못된 공식 URL·필수 근거 누락이 있으면 빌드가 실패합니다.
- 공개 작품 페이지의 관련 목록은 소규모 소개 목록의 갈래·태그를 비교합니다. Backend의 개인화 유사도와 구분하며 퍼센트·평점·인기 순위로 표시하지 않습니다. `/?seed=작품ID`는 작품을 선택한 첫 화면으로 연결하고 대표 주소는 `/`입니다.
- `dist/robots.txt`, `dist/sitemap.xml`을 빌드에서 생성합니다. 확인되지 않은 lastmod 날짜를 넣지 않습니다. `VERCEL_ENV=preview` 또는 `SEO_NOINDEX=true`에서는 모든 문서가 noindex이고 사이트맵은 비웁니다.
- `vercel.json`은 API 프록시와 보안 헤더를 유지하고 API에 `X-Robots-Tag: noindex`를 추가합니다. 공개 문서 경로만 명시적으로 정적 HTML에 연결하고 없는 주소는 플랫폼의 실제 404를 반환합니다. `.html` 정리는 해당 공개 문서에만 적용하며 Google 소유권 확인 파일의 원래 주소는 유지합니다. 로컬 Vite 개발 서버의 SPA fallback을 운영 404 검증으로 사용하지 마세요.
- Paperlogy는 글리프를 제거하지 않은 WOFF2 3종을 로컬 제공하며 `public/fonts/OFL.txt`에 라이선스를 포함합니다. 작은 로고·96px 파비콘·Apple 아이콘과 원래 아이콘의 공유 이미지를 사용합니다.
- 빌드 검사는 제목·설명 중복, canonical, JSON-LD, 하나의 H1, 깨진 링크·고립 문서, 사이트맵, 프록시 정책을 확인합니다. `npm run test:seo`로 생성물 검사를 다시 실행할 수 있습니다. 미리보기 테스트 후에는 운영 환경으로 다시 빌드하세요.

외부 설정은 별도입니다. 가비아에서 www DNS 및 Vercel 도메인 등록이 되어야 www 리디렉션이 동작합니다. Google Search Console 도메인 소유 확인·네이버 서치어드바이저 등록·사이트맵 제출은 실제 계정의 확인 값으로 진행해야 합니다. 계정 접근·소유 확인·검색 색인·검색 순위·실사용자 CWV 통과를 코드 빌드 성공만으로 완료 처리하지 않습니다. 연락 수단은 프로젝트의 공개 문의 게시판으로 연결했으며 공개 정보만 남기도록 안내합니다.


## 2026-11-07 운영 검증

운영 모노레포 main의 최신 카탈로그(7,372개)를 유지한 채 SEO 문서 43개와 별도 404 페이지를 배포했습니다. 다른 작업 중인 Backend·크롤러 변경은 이 SEO 배포에 포함하지 않았습니다.

- 빌드 시 생성물 검사 통과: 고유 제목·설명·canonical, 초기 HTML 본문/H1, 내부 링크와 고립 페이지, JSON-LD, 사이트맵/preview 정책. 프론트엔드 단위 테스트 12개 통과.
- 운영 사이트맵의 공개 URL 43개를 HTTP로 확인했습니다. robots TXT·사이트맵 XML·API JSON/noindex, 원래 Google 확인 파일 주소 200, 잘못된 URL의 사용자용 HTML 404를 확인했습니다.
- 브라우저에서 장르→작품→작품 자동 선택→분석→추천 10개, 카카오 필터, 재검색 10개 간 중복 없음, 콘솔 오류 없음, 390px 작품 화면의 가로 넘침 없음을 확인했습니다.
- Google Search Console이 사이트맵을 처리하고 43개 페이지를 발견했습니다. 표본 작품 URL의 실시간 테스트는 색인 가능과 유효한 탐색경로를 표시했고 작품·홈페이지 색인 요청이 접수됐습니다. 네이버도 사용자의 로그인·보안문자 확인 후 소유 확인을 완료하고 같은 사이트맵을 등록했습니다. 발견·접수는 실제 색인 완료를 뜻하지 않습니다.
- 모바일 PageSpeed API는 검사 시 429를 반환해 Lighthouse 점수를 확보하지 못했습니다. 실사용자 Core Web Vitals는 Search Console에 아직 데이터가 없어 통과 여부를 판정하지 않았습니다.
- www 호스트는 공개 DNS 조회에서 아직 NXDOMAIN입니다. 홈페이지의 대표 주소는 정상 작동하며 www를 사용하려면 가비아 DNS와 Vercel 도메인 등록을 완료해야 합니다. 코드에는 www→대표 도메인 영구 리디렉션을 준비했습니다.
- 검색 노출·클릭·CTR과 추천 완료율의 지속 개선은 이후 운영 과제입니다. 예산·DNS·분석 도구·예약 작업을 임의로 새로 생성하지 않았습니다.
